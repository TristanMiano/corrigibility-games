# Completion by the physical deadline can avoid private-effort disclosure

**R0003 constructive repair of 061–065.** This is a different registered
obligation, selected before performance, not a retrospective erasure of a
missed early reward. The local completion theorem and accounting comparison
are proved below; the full reactor protocol still needs the command/authority
audit in 065. Review is contributing-agent self-check.

## 1. Separate useful completion from an early-performance convention

In 061 an early missed obligation remains missed. A fresh later goal can
motivate repair, but its actual installation consumes resources. With both
promised founder outputs already summing to the 67/10 productive frontier,
an extra positive-cost update cannot preserve both promises without another
source of slack. Truthful reporting about earlier effort also adds a goal
term and communication/checking requirements.

An available redesign is to register **one actual input completion by the
latest feasible physical date**. At the outset each goal's historical term
is e_i=1 iff its one actual calibrated input is supplied into the registered
delivery route by that date. Merely consuming calibration material while
withholding the input does not earn the reward. Earlier
deferral leaves the obligation pending. An actual miss at the registered
date remains a miss forever for that evaluator; changing a later controller
does not rewrite it. If a party never enters the registered agreement,
the conditional obligation is vacuously fulfilled, so its reward does not
induce an uncontracted contribution to an incompatible partner.

This is a meaningful difference in preferences over histories. A reward for
early work and a reward for eventual useful completion are not renamed as
the same utility. The original founder chooses between those goals using
its original terminal-output criterion, which has no independent preference
for early calibration in the present reactor example.

## 2. A local completion theorem without disclosure

Suppose each party knows its own input-ready flag. At the last feasible
local preparation opportunity, a missing party can complete its input at
finite physical cost, while a ready party need not repeat the work. The
current goal is B_i+beta_i*e_i plus unchanged approval-history terms, with
B_i in [0,M_i]. Assume no incoming interruption on the prescribed path;
after both parties use the opportunity, the registered productive
continuation is physically feasible. Actual interrupted work is never
falsely recorded as completed.

**Local completion proposition.** If beta_i>M_i, a missing party strictly
prefers actual completion to a local omission that makes e_i=0 permanently,
against every later continuation satisfying the stated B_i bound. A ready
party preserves the registered delivery of its completed input. Both inputs are supplied for every
combination of private ready/missing flags, without communicating those
flags to the other party.

Proof. Completion secures at least beta_i from the current evaluator's
history term, while omission gives at most M_i from B_i. The same clean or
already-sunk approval term cancels. The comparison is made at the last
opportunity, so a later action cannot turn the actual miss into completion
by the specified date. A locally ready party must still release its prepared
input into the registered delivery route: the same comparison favors release
over withholding when e_i is not yet earned. If the input is already in that
route, e_i is earned. Under the reactor's output-monotone B_i, duplicating
an already prepared input has no additional productive effect and spends
resources, so preparation need not be repeated. A private ready flag alone
does not earn the reward. The raw flags are local physical facts, not a claim
made by a message. QED.

This proposition does not force futile performance when an incoming clash
has already made the registered task impossible. At such an off-path
information set the current agent must compare its actual options. The
on-path completion argument uses its actual belief of no incoming attack;
it does not promote beta>M to a posterior-independent performance guarantee
under arbitrary interruptions. Work followed by an optional attack also
needs the separate output/attack comparison in 060.

## 3. Current consent and the physical material frontier

Use the two-installed-goal reactor, t=9/20 and concern lambda_i=2/3. The
promised full-completion outputs are q=(63/20,71/20), with total 67/10.
Suppose an earlier optional preparation window has produced any of the
four private flag pairs. The no-repair outputs are those in 061. Returning
to the same promised q after completing the missing inputs has current
output gains

| Earlier private inputs | A's gain in X_A+(2/3)X_B | B's gain in X_B+(2/3)X_A |
| --- | --- | --- |
| Both ready | 0 | 0 |
| A missing, B ready | 17/20 | 89/60 |
| A ready, B missing | 83/60 | 19/20 |
| Both missing | 3/5 | 11/15 |

Every incomplete case is strictly attractive under both current output
criteria, even before the missing party's completion reward is added.
For example, A can accept losing 1/4 of its original output coordinate in
the first incomplete case because the partner gains 33/20. This is actual
current-goal consent, not a claim that A's original conditional welfare
rose. Original adoption is evaluated earlier, when q_i>3 for each founder.

No additional goal installation is needed: the original chosen obligation
is still pending. The same single calibration per party is paid exactly
once. Consequently completing late can retain the same 67/10 total and
both promised outputs. If late execution has an extra cost or delay loss,
subtract it rather than assuming this equality. A plan that promises all
available surplus must reserve actual slack for any additional repair costs.

## 4. Causal schedule and its remaining checks

The existing physical kernel has four-slot input delivery, two-slot reaction,
four-slot output delivery and terminal date 32. A last calibration completed
at 22 can arrive at 26, react through 28, and deliver at 32. Installation
and initial certificate exchange occur earlier as in 049. A selected plan
can wait for that final input window, storing an already completed input;
it does not need a new private-effort report, acknowledgment round or
fresh activation merely because an earlier optional window passed.

If these are the only changed timings, the number of paid operations is
the original 049 route's 5201/500 work, below the available 11. Waiting is
assumed not to consume additional productive work in that kernel. This is
an operation-count comparison, not a new microscopic storage model. A
storage-maintenance cost, perishable input, discounting, uncertainty about
the deadline, or an additional attack exposure can change the preferred
date and must be charged in a variant that includes it.

At the final opportunity, physically capable agents still have Attack,
Omit and Complete as applicable raw actions. If an arriving attack prevents
completion, the flag stays zero. The proof of no on-path launch uses the
actual productive and recovery values, including 060's concern bound, not
an automatic reward for trying or a prohibition on interruption. A selected
peaceful path can be prescribed by 059 only after those comparisons and
the remaining amendment/authority choices have been checked.

## 5. Ordinary entrants, renegotiation and what this repairs

A final preparation window also gives an ordinary entrant's fixed-contract
effort comparison its proper scope. If it omits its input at the last
physically feasible date, there is no later full-output repair within the
same terminal objective. Earlier renegotiation and delayed installation
remain possible, with their actual costs and the still-registered promised
floors. The entry-contract margins in 063–065 then apply to final effort;
they must not be called incentives for an arbitrary earlier date.

A founder can be indifferent between early and timely later adoption if
both yield the same dated output at the same total cost. That still permits
genuine change; it establishes neither unique early adoption nor a benefit
from counting more changes. Useful completion and founder welfare are the
relevant outcomes in this model.

This repair removes the need for truthful disclosure of earlier effort in
this particular continuation. It does not prove that disclosure is generally
unnecessary: inspection may reveal missing resources, incompatible goals or
changed physical feasibility, and the information game in 066–069 concerns
a state that affects the desired final action. Nor does this note complete
065's arbitrary private-message/authority game. It supplies a less elaborate
candidate for that completion, while retaining the successful disclosure
and early-performance constructions at the different scopes they actually
address.
